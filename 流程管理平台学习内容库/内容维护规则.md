# 内容维护规则

## 一篇内容的基本结构

1. 学习目标
2. 核心概念或操作说明
3. 示例、表格或步骤
4. 注意事项
5. 来源与状态

## 修改流程

```text
编辑草稿 → 自查来源 → 业务审核 → 标记 published → 构建网页 → 内网验收
```

在 Obsidian 的“属性”中设置 `status`：`draft` 为草稿，`review` 为待审核，`published` 为已审核并允许进入发布包，`deprecated` 为停用。缺少状态的文件不会生成；请勿用中文“发布”代替 `published`。

- 点击左侧“生成 BPA 本地预览”：包含 `draft`、`review`、`published`，输出到项目目录的 `构建结果/本地预览/`，只供本机检查。
- 文章的 `category` 决定培训课程中的分类；填写单行文本属性 `guide_group`（例如 `登录与进入平台`）后，同一篇文章还会出现在网站的操作指南对应分类。不填写则不进入操作指南，但仍可出现在课程和搜索中。
- 生成本地预览时会同步更新 `02-操作指南/00-操作指南导航.md` 中标记之间的自动生成区域，包含草稿，仅供本地使用；请勿手改标记区域，可在区域外记录内容。修改分类或文章标题、文件名后重新生成预览。发布包单独按已发布文章生成，不使用该导航文件，也不会更新它。
- 点击左侧“生成 BPA 已发布内容”：只包含 `published`，输出到 `构建结果/发布包/`；它不会自动上传或部署。重新生成会移除不再发布的文章和资源。
- 发布文章指向未发布笔记、引用丢失文件或使用不支持的资源类型时，构建报错并保留上一份结果。审核文章所引用的每张图片和附件，确保可供目标读者访问；共享资源会随已发布文章一同进入发布包。
- 不要把项目根目录、旧原型、本地预览或构建备份当作发布包上传。状态不是访问控制；内网权限、缓存清理、历史版本和部署方式需另行落实。
- 当前支持图片和 PDF、DOCX、XLSX、PPTX、ZIP 附件下载；SVG、嵌入笔记、Mermaid 和公式尚未支持。生成页面沿用旧原型的视觉和布局，文章、目录及搜索内容来自按状态筛选的 Markdown；旧原型本身仍是独立页面，不受状态筛选。
- 插件代码更新后，重启 Obsidian 或在第三方插件设置中停用再启用该插件。操作也可通过命令面板或自设快捷键执行。

## 内容边界

- 不将原型草稿表述为正式 SOP。
- 不编造现网菜单、按钮、权限、审批人或发布规则。
- 涉及权限、发布、作废等高风险内容，必须经过业务确认。

## Git 与网站更新

内容库和网站代码直接位于项目 Git 仓库中，不需要复制到独立部署仓库。修改后可点击“检查 BPA Git 更改”查看待提交文件；该操作会先保存当前文档，不会提交或推送。确认更改后在项目 Git 仓库提交并推送到 GitHub，EdgeOne 按配置构建已发布内容。草稿可以存入私有 Git 仓库，但只有 published 文章进入网站。公开预览链接可被持有者访问，推送前请检查文章和附件的发布范围。

插件更新后，在 Obsidian 第三方插件设置中关闭并重新启用“BPA 网页内容更新”，或重启 Obsidian。

点击“检查并推送 BPA 网站更新”会先保存当前文档、生成本地预览并检查发布构建，列出全部待提交文件供确认。确认后才会提交并推送；EdgeOne 的构建结果仍需到控制台查看。存在暂存文件、远端版本不一致或确认后文件发生变化时会停止。如果提交成功但推送失败，本地提交会保留，需先检查 Git 状态后处理，不要重复提交。
